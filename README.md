# UmamiTaste

Code and configuration files accompanying a study of graph neural network (GNN)-based umami taste prediction and interpretation.

## Repository scope

This repository documents data processing, model configuration, scaffold-disjoint cross-validation, Integrated Gradients (IG) analysis, functional-group comparisons, matched-pair analysis, conventional machine learning baselines, scaffold sensitivity analysis, and figure generation. It does **not** include pretrained model checkpoints, training logs, bulk IG outputs, or the source ChemTastesDB Excel workbook.

The repository is intended to make the analysis procedures and the dataset partitions transparent. It is **not** a self-contained, one-command reproduction package: some stages require source data, a separately installed kMoL environment, model checkpoints generated by training, and intermediate outputs.

## Data

The analysis uses ChemTastesDB-derived small-molecule data. Obtain the source dataset from its original provider, subject to its terms of use. The preprocessing scripts expect `data/raw/ChemTastesDB_database.xlsx` as input; this file is **not included** here.

Three study datasets were considered:

| Dataset | Umami | Non-umami | Total | Negative selection |
| --- | ---: | ---: | ---: | --- |
| Strict | 74 | 209 | 283 | Tasteless compounds |
| Full primary | 74 | 2,320 | 2,394 | Non-umami compounds |
| Physicochemical-property-matched | 74 | 74 | 148 | Matched negative compounds |

The exact five-fold scaffold assignments are provided under `data/kmol/`. These assignments should be used when comparing against the reported cross-validation results, rather than generating new random partitions.

### Source-data and redistribution note

The ChemTastesDB workbook is not redistributed here. Any redistribution of derived molecule-level tables should be assessed against the original data provider's terms. The repository's inclusion of scripts and split files does not itself grant rights to redistribute the source dataset.

## Software

The original analysis used the following software versions:

| Component | Version |
| --- | --- |
| Python | 3.11.16 |
| RDKit | 2022.09.4 |
| PyTorch | 1.13.1 |
| PyTorch Geometric | 2.3.0 |
| kMoL | Commit `92715aaa00a909f62b9c36f5fdd9bd1fb505dba3` |

The GNN was implemented using the kMoL framework. The study configuration used an LEConv-based architecture with seven message-passing layers, a hidden dimension of 96, dropout of 0.1, and both atom-level and molecule-level input features. Training used AdamW and a OneCycle learning-rate schedule, with a maximum of 100 epochs and batch size 32. Dataset-specific configurations are provided in `configs/kmol/`.

**Environment reproducibility:** The versions above document the original software stack; a complete, independently validated installation procedure and lockfile are not provided. In particular, compatible PyTorch, PyTorch Geometric, and kMoL installations may require platform-specific setup.

## Workflow overview

The steps below describe the order of analysis. They are **not** a fully tested end-to-end command sequence. Where a script accepts required command-line arguments, consult its `--help` output and the paths documented in the script.

1. **Dataset preparation:** `src/01_prepare_chemtastesdb.py` reads the source workbook; `src/02_finalize_umami_dataset.py` standardizes and deduplicates the umami molecules; `src/03_prepare_negative_dataset.py` constructs the negative sets; and `src/04_prepare_training_sets.py` assembles the study datasets, including physicochemical matching.
2. **kMoL input and cross-validation:** `src/06_prepare_kmol_input.py` prepares molecular inputs. The `07_`, `08_`, and `09_` scripts prepare scaffold partitions, model inputs, and/or kMoL configurations. Use the published scaffold assignments to preserve the study's folds.
3. **Model training and evaluation:** Train and evaluate the GNN using the relevant files in `configs/kmol/` with a compatible installation of kMoL. `umami_criterions.py` provides the custom loss used by the weighted configuration. The model checkpoints are generated during training and are not distributed.
4. **Out-of-fold IG:** Use `src/10_select_best_fold_checkpoints.py` and `src/10_make_ig_fold_configs_v2.py` as applicable to prepare fold-specific IG analysis. `src/10_export_signed_ig_v2.py` exports signed atom-level attributions; `src/11_merge_and_annotate_ig.py` combines and annotates the fold outputs.
5. **Interpretation:** `src/12_compare_functional_group_ig.py` performs functional-group comparisons, while `src/13_analyze_matched_pairs_ig_v2.py` examines structurally related molecule pairs. `src/17_matched_pair_sensitivity.py` provides a sensitivity analysis.
6. **Conventional ML baselines and scaffold sensitivity:** `src/19_run_ml_baselines.py` evaluates random forest and XGBoost classifiers on the fixed scaffold folds. `src/20_audit_scaffold_cv.py` audits scaffold assignments and identifies the dominant umami-associated scaffold. `src/21_scaffold_sensitivity.py` recalculates evaluation metrics after excluding compounds belonging to that scaffold from existing out-of-fold predictions; it does not retrain the models.
7. **Figures:** `src/14_make_matched_pair_figure_v3.py`, `src/15_make_performance_figure_v4.py`, `src/16_make_functional_group_figure_v2.py`, and `src/18_make_study_design_figure.py` generate the corresponding visualizations.

### Important input/output dependencies

- The initial preprocessing scripts require the source workbook and generate intermediate CSV files in `data/interim/`, `data/processed/`, and `data/model_sets/`.
- IG extraction requires fold-specific trained model checkpoints. The IG configurations may contain paths specific to the original machine and should be adapted before reuse.
- The matched-pair analysis requires the preceding similarity/MCS and IG analysis outputs.
- `src/15_make_performance_figure_v4.py` reads original training-log directories. Those logs are not distributed; the small `figure2_metrics.csv` and `figure2_physchem_smd.csv` summary tables are provided for reference, but they do not make the plotting script directly executable without its expected log inputs.

## Model evaluation and interpretation

The study assessed discrimination under five-fold scaffold-disjoint cross-validation. Reported mean performance values are summarized below; standard deviations reflect variation across folds.

| Dataset | ROC-AUC | PR-AUC |
| --- | --- | --- |
| Strict | 0.935 ± 0.054 | 0.824 ± 0.148 |
| Full primary | 0.950 ± 0.036 | 0.722 ± 0.197 |
| Physicochemical matched | 0.910 ± 0.082 | 0.866 ± 0.131 |

For model interpretation, signed atom-level Integrated Gradients were computed on out-of-fold predictions. Functional-group-level analyses and matched-pair comparisons were then performed using the exported attribution data. These attributions describe model behavior; they are **not** direct experimental evidence of molecular taste mechanisms.

## Conventional machine learning baselines and scaffold sensitivity (Tables S6–S7)

Three conventional classifiers were evaluated on the **same predefined Murcko scaffold-disjoint five-fold partitions** used for the GNN: random forest with radius-2, 2048-bit Morgan fingerprints; XGBoost with RDKit molecular descriptors; and XGBoost with both Morgan fingerprints and RDKit descriptors. The analysis uses fixed hyperparameters rather than tuning on held-out folds. Results are reported as the mean and standard deviation of fold-level ROC-AUC and PR-AUC in **Supplementary Table S6**.

| Dataset | Model | ROC-AUC (mean ± SD) | PR-AUC (mean ± SD) |
| --- | --- | ---: | ---: |
| Strict | RF / Morgan | 0.9780 ± 0.0255 | 0.9540 ± 0.0436 |
| Strict | XGBoost / RDKit | 0.9553 ± 0.0521 | 0.8911 ± 0.1226 |
| Strict | XGBoost / Morgan + RDKit | 0.9702 ± 0.0403 | 0.9314 ± 0.0915 |
| Full primary | RF / Morgan | 0.9437 ± 0.0448 | 0.6402 ± 0.2621 |
| Full primary | XGBoost / RDKit | 0.9689 ± 0.0379 | 0.7504 ± 0.2206 |
| Full primary | XGBoost / Morgan + RDKit | 0.9779 ± 0.0253 | 0.7464 ± 0.2181 |
| Physicochemical matched | RF / Morgan | 0.8829 ± 0.1367 | 0.8673 ± 0.1553 |
| Physicochemical matched | XGBoost / RDKit | 0.8722 ± 0.1365 | 0.8363 ± 0.1798 |
| Physicochemical matched | XGBoost / Morgan + RDKit | 0.8730 ± 0.1299 | 0.8171 ± 0.2062 |

The baseline analysis writes fold-level metrics, out-of-fold predictions, and summary files under `results/jcim_baselines/`. The scaffold audit and sensitivity analyses use these predictions and write supporting outputs under `results/jcim_scaffold_audit/` and the sensitivity script's configured output directory. Some inputs or results may not be included in the public repository; consult the scripts for the required arguments and paths before running them. **Do not assume that the three scripts form a tested, one-command reproduction pipeline.**

### Dominant-scaffold sensitivity analysis

The dominant umami-associated Murcko scaffold includes **32 of 74 umami compounds (43.2%)**. The scaffold audit checks the original fold assignments for scaffold overlap. The post hoc sensitivity analysis then excludes these 32 compounds **only when scoring existing out-of-fold predictions**, without retraining any model. **Supplementary Table S7** reports pooled out-of-fold ROC-AUC and PR-AUC before and after this exclusion. These pooled scores are calculated differently from the fold means in Table S6 and should not be compared as interchangeable estimates. The positive-class prevalence also changes after exclusion, affecting the interpretation of PR-AUC.

The analysis does not demonstrate that a retrained model would retain its performance without the dominant scaffold, and it does not establish the GNN's performance after scaffold exclusion.

## Notes on reproducibility

- The original relative paths and script filenames are retained where possible.
- Model weights, training logs, and large intermediate IG outputs are intentionally omitted.
- Some generated IG configurations may contain machine-specific paths and require editing before use.
- The exact scaffold folds are included, but reproduction of the numerical results also depends on the original data, environment, model-training procedure, and any stochastic settings.
- Conventional ML baseline scripts require scikit-learn and XGBoost in addition to RDKit; their exact installed versions should be recorded separately if they differ from the original GNN environment.
- The baseline fold-level metrics and sensitivity outputs are generated artifacts; verify that the intended output files and input CSVs are present before claiming end-to-end reproducibility.
- The public package should be checked for sensitive local paths and source-data redistribution restrictions before release.
